1. Visión general

Operantia es una SPA (Single-Page Application) para gestión de flotas municipales. Tiene dos zonas diferenciadas: la app de campo (conductores — rutas /, /incidencias, /inventario) y el workspace de planificación (jefes de oficina — rutas /login → /projects → /planning → /scheduling). Ambas comparten el mismo bundle Vite pero el entry point main.jsx decide qué renderizar según la URL.

TecnologíaUso
React 19 + Vite 8Framework y bundler. HMR en desarrollo. Build ~1.45 MB (gzip ~435 KB).
Firebase FirestoreBase de datos en tiempo real. Sin backend propio.
Leaflet 1.9.4 (CDN)Mapas interactivos en Planning y App. Cargado en runtime (no npm).
OSRM (API pública)Routing por carretera para medición de distancias en Planning. Sin API key.
SheetJS (xlsx npm)Parsing de archivos Excel (.xlsx) en Planning.
Inline styles (C.*)Sistema de diseño. Constantes de color y fuente definidas como objetos JS. Sin CSS modules.

7. Algoritmo VRP

  1. K-means geográfico (maxIter=15): agrupa paradas en k clústeres (k = nº vehículos).
  2. TSP vecino más cercano: ruta greedy dentro de cada clúster desde el punto más cercano al depot.
  3. 2-opt (maxPasses=min(20,n)): mejora intercambiando pares de aristas.
  4. Ventanas de turno: turnoWindow() parsea «Tarde (14-22)» → {start:840, end:1320}.
  5. Multi-día rolling: paradas no asignadas en el día N se re-clústerizan en el día N+1. daysUsed se calcula automáticamente.

Arquitectura vehicle ↔ worker

  • Vehículos corren VRP con su turno (fuente de verdad).
  • Trabajadores vinculados (vehiculoId): copian exactamente las asignaciones del vehículo.
  • Trabajadores no vinculados: corren VRP independiente sobre todas las tareas.
  • Velocidad: TRAVEL_SPEED_KMH = 30. Umbral mínimo de movimiento: 50m.

8. Sistema de colores por barrio

  • Por defecto: hash de Horner (multiplicador 31) → índice en paleta de 12 colores. Determinista — mismo barrio, mismo color siempre. Cache en _barrioCache.
  • Personalizable (Planning): el usuario puede cambiar el color de cualquier barrio con un color picker. Overrides guardados en fc_barrio_colors_{projectId}. barrioColor(b, overrides) consulta overrides primero.
  • Paleta default: #4f8ef7 #fb923c #34d399 #f87171 #a78bfa #fbbf24 #f472b6 #22d3ee #818cf8 #4ade80 #e879f9 #2dd4bf
  • Sin barrio → gris #8b95a5.

9. Auth y Roles

  • Auth workspace: usuario/contraseña contra colección Firestore usuarios o array USUARIOS_INIT. Sesión en localStorage bajo fc_session. No usa Firebase Auth.
  • Rol "admin": subir KML, borrar planes, gestionar usuarios, cambiar estado incidencias.
  • Rol "conductor": reportar incidencias, marcar paradas, ver inventario.
  • Planificadores: cualquier usuario autenticado en /login puede acceder a /projects, /planning, /scheduling.
